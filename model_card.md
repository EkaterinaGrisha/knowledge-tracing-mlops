# Model Card: `kt-dkt`

Модель оценки знаний ученика (knowledge tracing) для адаптивной обучающей
платформы по школьной математике. Карточка составлена по шаблону Google
Model Card Toolkit: Model Details, Model Parameters, Quantitative Analysis,
Considerations.

## Model Details — сведения о модели

### Overview — обзор

`kt-dkt` по истории ответов ученика оценивает, насколько он владеет каждым из
109 навыков школьной математики: для каждого навыка модель возвращает
вероятность того, что следующее задание на этот навык ученик решит правильно.

- **Назначение.** Модель работает внутри адаптивной обучающей платформы: по её
  прогнозам платформа выбирает следующее задание и отмечает освоенные навыки,
  а учитель видит, какие темы требуют внимания класса. Место модели в
  процессе — [Model_BPMN.md](Model_BPMN.md).
- **Решаемая задача.** Предсказание правильности следующего ответа ученика по
  последовательности его предыдущих ответов — бинарная классификация с
  вероятностным выходом.
- **Тип модели.** Deep Knowledge Tracing (Piech et al., 2015) — рекуррентная
  сеть LSTM; архитектура и гиперпараметры подобраны Optuna (в проекте модель
  называется DKT+Optuna).
- **Данные для обучения.** Открытый датасет ASSISTments 2009–2010: 215 673
  ответа 3 862 учеников.

### Version — версия

- Модель хранится в MLflow Model Registry под именем `kt-dkt`. Рабочая версия
  помечена алиасом `champion`, новая версия-кандидат — `challenger`; выпуск
  новых версий описан в [Model_retrain_BPMN.md](Model_retrain_BPMN.md).
- Описанная версия обучена 5 октября 2026 г. на полном датасете (seed 42).

## Model Parameters — параметры модели

### Model Architecture — архитектура

- Каждый ответ кодируется парой «навык, правильность» — индексом
  `2 · skill + correct`.
- Слои: `Embedding` (32) → `LSTM` (скрытое состояние 128) → `Dropout` (0.49) →
  линейный слой на 109 навыков → сигмоида. Выход после ответа *t* —
  вероятность правильного ответа на шаге *t + 1* по каждому навыку.
- Обучение: Adam, learning rate 0.0043, batch 32, 30 эпох; функция потерь —
  бинарная кросс-энтропия по навыку следующего шага; норма градиента
  ограничена значением 5.
- Подбор архитектуры: Optuna (TPE), 25 испытаний по 8 эпох, критерий —
  ROC-AUC на валидационной выборке (лучшее значение 0.8180). Пространство
  поиска: `embed_dim` и `hidden_dim` ∈ {32, 64, 128}, `dropout` ∈ [0, 0.5],
  `lr` ∈ [1e-3, 2e-2], `batch_size` ∈ {16, 32, 64}.
- Окружение: Python 3.11, PyTorch 2.6 (CPU); точные версии библиотек — в
  `poetry.lock`.

### Data — данные

ASSISTments 2009–2010 *skill builder* (обновлённая версия, зеркало
репозитория DKVMN): для каждого ученика — последовательность навыков и
правильности ответов.

| | Значение |
|---|---|
| Ответов после очистки | 215 673 |
| Учеников | 3 862 |
| Навыков | 109 |
| Доля правильных ответов | 63.5 % |
| Train / validation / test, учеников | 2 704 / 386 / 772 |
| Train / validation / test, ответов | 150 517 / 19 803 / 45 353 |

- Предобработка: удаляются строки с пропусками и некорректными метками; у
  каждого ученика остаются первые 200 ответов; ученики меньше чем с тремя
  ответами исключаются.
- Разбиение по ученикам (70 / 10 / 20 %, seed 42), чтобы история одного
  ученика не попадала одновременно в обучение и тест. Validation используется
  только для подбора архитектуры, test — только для итоговой оценки.
- Перед обучением данные проходят пять проверок качества: схема, пропуски,
  метки 0/1, диапазон навыков, уникальность пары `user_id, order_idx`. Дрейф
  между train и test не обнаружен: максимальный PSI 0.0079 при пороге 0.10.

### Input Format — входные данные

CSV с историей ответов, одна строка — одна попытка ученика (пример —
[examples/history.csv](examples/history.csv)):

| Поле | Тип | Описание |
|---|---|---|
| `user_id` | идентификатор | ученик |
| `order_idx` | целое число | порядковый номер попытки ученика |
| `skill_id` | целое число | навык по классификации ASSISTments |
| `correct` | 0 или 1 | ответ неправильный или правильный |

Попытки упорядочиваются по `order_idx`. Ответы по навыкам, которых не было в
обучающих данных, пропускаются с предупреждением; отсутствующий столбец или
значение `correct`, отличное от 0 и 1, — ошибка.

### Output Format — выходные данные

Одна строка на пару «ученик — навык», 109 строк на ученика:

| Поле | Описание |
|---|---|
| `user_id` | ученик |
| `skill_id` | навык |
| `p_correct` | вероятность (от 0 до 1) правильного ответа на следующее задание по навыку |

```bash
kt predict --input examples/history.csv                                  # модель из artifacts/model
kt predict --model models:/kt-dkt@champion --input examples/history.csv  # рабочая версия из MLflow
```

## Quantitative Analysis — количественный анализ

### Performance Metrics — метрики качества

Оценка выполнена на тестовой выборке (772 ученика) по протоколу
one-step-ahead: каждый ответ предсказывается только по предыдущим ответам того
же ученика, поэтому для первого ответа ученика прогноза нет.

- **ROC-AUC** — основная метрика: качество ранжирования вероятностей без
  выбора порога, стандарт для задач knowledge tracing, устойчива к дисбалансу
  классов (63.5 % правильных ответов).
- **Accuracy, F1, precision, recall** — при пороге 0.5.
- **RMSE и log-loss** — качество самих вероятностей; калибровочная кривая
  показывает, насколько вероятности соответствуют фактической доле
  правильных ответов.
- **Порог качества** для выпуска новой версии — ROC-AUC не ниже 0.75 на тесте.

| Метрика | Значение |
|---|---|
| ROC-AUC | **0.8036** |
| Accuracy | 0.7525 |
| F1 | 0.8195 |
| Precision | 0.7650 |
| Recall | 0.8824 |
| RMSE | 0.4110 |
| Log-loss | 0.5106 |
| Предсказанных ответов | 44 581 |

Сравнение с альтернативами на тех же данных и по тому же протоколу:

| Модель | ROC-AUC | Accuracy | F1 | RMSE |
|---|---|---|---|---|
| BKT — байесовская модель, базовая | 0.7200 | 0.7046 | 0.7888 | 0.4440 |
| AutoML (FLAML, xgboost) на табличных признаках | 0.7919 | 0.7455 | 0.8170 | 0.4146 |
| DKT без подбора архитектуры | 0.8015 | 0.7504 | 0.8175 | 0.4129 |
| **DKT+Optuna (`kt-dkt`)** | **0.8036** | 0.7525 | 0.8195 | 0.4110 |

| 10–19 | 5 350 | 0.8144 |

| Навыки по числу ответов в train | Ответов в тесте | ROC-AUC |

заметно ниже на редких навыках (0.722): для них мало обучающих примеров.

## Considerations — особенности применения

### Users — пользователи

- Адаптивная обучающая платформа — получает прогнозы через `kt predict` или
  pyfunc-модель MLflow.
- Учителя и методисты — видят агрегированные показатели освоения навыков, а
  не сырые вероятности.

### Use Cases — сценарии применения

- Выбор следующего задания: в приоритете навыки с низкой вероятностью
  правильного ответа.
- Определение момента освоения навыка: вероятность выше порога, который
  задаёт платформа.
- Панель учителя: освоение навыков по классу перед уроком.

Вне рамок применения: выставление оценок, аттестация и другие решения с
высокими ставками о конкретном ученике; другие предметы и классификации
навыков без переобучения; ученики без истории ответов.

### Limitations — ограничения

- **Холодный старт.** До первого ответа ученика прогноза нет; новым ученикам
  нужна стартовая диагностика.
- **Редкие навыки.** ROC-AUC 0.722 — оценки по ним менее надёжны.
- **Фиксированный набор навыков.** Навыки вне 109 известных модели
  игнорируются; для новой программы обучения нужно переобучение.
- **Время не учитывается.** Модель не учитывает забывание и перерывы между
  попытками.
- **Особенности DKT.** Прогноз может колебаться от шага к шагу и иногда
  снижаться после правильного ответа (Yeung & Yeung, 2018).
- **Данные.** Одна платформа и одна популяция учеников (США, 2009–2010
  учебный год); перед применением на другой аудитории нужна проверка на её
  данных.
- **Оценка.** Одно разбиение и один seed, доверительные интервалы не
  оценивались.

### Tradeoffs — компромиссы

- **Точность и интерпретируемость.** DKT точнее BKT на 0.084 ROC-AUC, но её
  внутреннее состояние нельзя объяснить параметрами навыка, как у BKT.
- **Точность и стоимость обучения.** Подбор архитектуры Optuna добавил к DKT
  0.002 ROC-AUC при времени обучения в 10 раз больше (676 с против 63 с на
  CPU).
- **Порог 0.5.** Recall 0.88 при precision 0.77: модель чаще ожидает
  правильный ответ. Для решений лучше использовать сами вероятности и порог
  под конкретный сценарий.

### Ethical Considerations — этические риски

| Риск | Как снижается |
|---|---|
| Данные учеников | в обучающих данных только анонимные идентификаторы; при работе с новыми данными — согласие, минимизация, ограничение доступа к индивидуальным оценкам |
| Ярлык «слабый ученик» | прогнозы относятся к навыкам, а не к способностям; учитель видит агрегированные показатели; модель не используется для оценок |
| Петля обратной связи: платформа выбирает задания по прогнозам и меняет данные для следующего обучения | мониторинг дрейфа и качества, переобучение по процессу [Model_retrain_BPMN.md](Model_retrain_BPMN.md) |
| Неравное качество для разных групп учеников | в данных нет демографических признаков, поэтому различия не измерены; перед применением на новой аудитории — проверка на её данных |
| Автоматические решения об ученике | прогноз — вспомогательный сигнал, решения об ученике принимает учитель |
