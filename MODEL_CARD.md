## 1. Сведения о модели

- **Архитектура.** Каждое взаимодействие (навык, правильность ответа)
  кодируется индексом `2 · skill + correct` → `Embedding` размерности
  32 → однослойная `LSTM` со скрытым состоянием 128 →
  `Dropout` 0.49 → линейный слой на 109 навыков →
  сигмоида. Выход после шага *t* — вероятность правильного ответа на шаге
  *t + 1* для каждого навыка (Piech et al., 2015).
- **Обучение.** Adam, learning rate 0.0043, batch 32, 30 эпох;
  функция потерь — бинарная кросс-энтропия только по навыку следующего шага;
  норма градиента ограничивается значением 5; seed 42 (веса, dropout,
  порядок батчей).
- **Подбор архитектуры.** Optuna (TPE), 25 испытаний по 8 эпох, критерий —
  ROC-AUC на валидационной выборке (лучшее значение
  0.8180). Пространство поиска: `embed_dim ∈ {32, 64, 128}`,
  `hidden_dim ∈ {32, 64, 128}`, `dropout ∈ [0, 0.5]`,
  `lr ∈ [1e-3, 2e-2]` (лог-шкала), `batch_size ∈ {16, 32, 64}`.
- **Программное окружение.** Python 3.11, PyTorch 2.6 (CPU); точные версии
  всех библиотек — в `poetry.lock`.
- **Артефакты.** `artifacts/model/` (`model.pt` — веса, `model.json` —
  архитектура, соответствие идентификаторов навыков, метаданные прогона);
  pyfunc-модель в MLflow: `models:/kt-dkt@challenger`, после согласования и
  `kt promote` — `models:/kt-dkt@champion`.
- **Ссылки.**
  - Piech C. et al. *Deep Knowledge Tracing*. NeurIPS, 2015.
  - Corbett A., Anderson J. *Knowledge tracing: Modeling the acquisition of
    procedural knowledge*. UMUAI, 1994 — BKT, базовая модель.
  - Feng M., Heffernan N., Koedinger K. *Addressing the assessment challenge
    with an online system that tutors as it assesses*. UMUAI, 2009 —
    ASSISTments.
  - Yeung C.-K., Yeung D.-Y. *Addressing two problems in deep knowledge
    tracing via prediction-consistent regularization*. L@S, 2018.
  - Mitchell M. et al. *Model Cards for Model Reporting*. FAT\*, 2019 —
    структура этой карточки.
- **Лицензия.** Учебный проект, лицензия на код не задана. Данные
  ASSISTments 2009–2010 распространяются для исследовательских и
  образовательных целей.

## 2. Назначение

**Основное применение.** Оценка текущего состояния знаний студента в
адаптивной обучающей системе по школьной математике: по истории ответов
модель возвращает вероятность правильного ответа на следующую попытку по
каждому из 109 навыков. Типичные сценарии — выбор следующего
упражнения (тренировать навык с низкой вероятностью успеха), определение
момента освоения навыка, агрегированные панели для преподавателя.

**Пользователи.** Разработчики образовательных продуктов (через
`kt predict` или pyfunc-модель MLflow); методисты и преподаватели — через
агрегированные показатели, а не через сырые вероятности.

**Вне рамок применения.**

- выставление оценок, аттестация, отбор и любые решения с высокими
  ставками о конкретном студенте;
- диагностика трудностей в обучении или оценка работы преподавателей;
- другие предметы, возрастные группы и таксономии навыков без повторного
  обучения и проверки (идентификаторы навыков жёстко связаны с ASSISTments
  2009, неизвестные навыки `kt predict` игнорирует);
- студенты без истории ответов: до первого ответа модель не может дать
  предсказание, новым студентам нужна стартовая диагностика (§8).

## 3. Факторы

- **Длина истории студента** — сколько попыток студента модель уже видела:
  не теряет ли она качество в начале работы со студентом и на длинных
  историях.
- **Частота навыка в обучающих данных.** Редкие навыки представлены
  меньшим числом примеров.
- **Популяция и время.** Американские школьники 2009–2010 учебного года,
  система ASSISTments; перенос на другую аудиторию не проверялся.
- **Не оценивалось:** демографические группы — в датасете нет
  демографических признаков, поэтому справедливость по группам студентов
  проверить невозможно.

Оценка по первым двум факторам приведена в §6.2.

## 4. Метрики

- **Основная — ROC-AUC:** качество ранжирования вероятностей без выбора
  порога, стандарт в литературе по knowledge tracing и устойчиво к
  дисбалансу классов (доля правильных ответов 63.5%).
- **Дополнительные:** accuracy, F1, precision и recall при пороге 0.5;
  RMSE и log-loss — качество самих вероятностей; калибровочная кривая.
- **Протокол:** one-step-ahead — каждая попытка тестового студента
  предсказывается только по его предыдущим попыткам; у DKT нет предсказания
  для первой попытки каждого студента, поэтому `n` у DKT меньше, чем у BKT
  и AutoML.
- **Неопределённость:** одно разбиение и один seed, доверительные
  интервалы не оценивались (см. §8).

## 5. Данные

**Источник.** ASSISTments 2009–2010 *skill builder* (обновлённая версия,
зеркало репозитория DKVMN), triplet-формат: длина последовательности,
список навыков, список правильности.

| | Значение |
|---|---|
| Взаимодействий после очистки | 215 673 |
| Студентов | 3 862 |
| Навыков | 109 |
| Доля правильных ответов | 0.6351 |
| Train / val / test, студентов | 2 704 / 386 / 772 |
| Train / val / test, взаимодействий | 150 517 / 19 803 / 45 353 |

**Предобработка.** Удаляются строки с некорректными метками и пропусками;
у каждого студента остаются первые 200 попыток; студенты с историей короче
трёх попыток исключаются; идентификаторы навыков отображаются в плотный
индекс. Разбиение — **по студентам** (70 / 10 / 20 %, seed 42), чтобы
история одного студента не попадала одновременно в обучение и тест.
Валидационная выборка используется только для подбора архитектуры Optuna,
тестовая — только для итоговой оценки.

**Проверки данных.** Data-quality gate пройден (все пять проверок); дрейф
признаков между train и test не обнаружен: статус `OK`,
максимальный PSI 0.0079 при пороге предупреждения 0.10.

## 7. Этические аспекты

- **Данные.** Идентификаторы студентов анонимизированы, персональных данных
  в датасете нет. При применении к новым данным действуют требования к
  обработке данных обучающихся: согласие, минимизация, ограничение доступа
  к индивидуальным оценкам.
- **Риск навешивания ярлыков.** Низкие вероятности не должны превращаться в
  характеристику ученика («слабый») и влиять на отношение к нему; модель
  оценивает навыки, а не способности человека.
- **Петля обратной связи.** Адаптивная система, выбирающая задания по
  предсказаниям модели, меняет распределение данных, на которых модель
  будет переобучаться; это контролируется мониторингом дрейфа (§8).
- **Справедливость.** Без демографических признаков различия качества
  между группами студентов не измерены — это ограничение, а не
  подтверждение отсутствия смещения.
- **Человек в контуре.** Предсказания — вспомогательный сигнал для
  адаптивной системы и преподавателя, а не автоматическое решение о
  студенте.

## 8. Ограничения и рекомендации

- **Холодный старт:** до первого ответа студента предсказания нет
  (студента без истории нет во входных данных `kt predict`); новым студентам
  нужна стартовая диагностика. По первым попыткам качество не хуже среднего
  (§6.2), но оценка опирается на общую сложность навыков, а не на знания
  конкретного студента.
- **Редкие навыки:** AUC 0.722 (§6.2) — оценки по ним менее
  надёжны; их стоит использовать осторожно и дообучать модель по мере
  накопления данных.
- **Время не учитывается:** DKT не моделирует забывание и интервалы между
  попытками.
- **Известные особенности DKT:** предсказания могут колебаться от шага к
  шагу и иногда снижаться после правильного ответа (Yeung & Yeung, 2018);
  интерпретируемость ниже, чем у BKT.
- **Фиксированная таксономия навыков:** навыки вне 109 известных модели
  игнорируются; для новой программы обучения нужно переобучение.
- **Старые данные и одна популяция:** 2009–2010 годы, одна платформа;
  перед применением на другой аудитории нужна проверка на её данных.
- **Одна оценка:** одно разбиение и один seed без доверительных интервалов.
- **Когда переобучать:** при значимом дрейфе признаков (PSI ≥ 0.25), при
  падении AUC на свежих данных ниже порога 0.75, при появлении новых
  навыков; плановое переобучение — раз в квартал
  ([жизненный цикл](docs/model_lifecycle.md)).

## 9. Использование

Вход — CSV с историей ответов: `user_id, order_idx, skill_id, correct`
(исходные идентификаторы навыков ASSISTments). Выход — одна строка на
студента и навык: `user_id, skill_id, p_correct`.

```bash
kt predict --input examples/history.csv                                 # локальный пакет artifacts/model
kt predict --model models:/kt-dkt@champion --input examples/history.csv  # рабочая версия из реестра MLflow
```

```python
import pandas as pd
from knowledge_tracing.inference import DKTPredictor

model = DKTPredictor.load("artifacts/model")
predictions = model.predict(pd.read_csv("examples/history.csv"))
```
